# DDP Server Climate Zones: server-side-only mod (confirmed via Steam Web
# API GetPublishedFileDetails: result=1, banned=0, visibility=0/public - its
# own Community page renders a stale/misleading "removed" banner, same as
# Sector31-DynamicHordes above; don't trust that page) that overrides
# WorldData.GetTemperature() for admin-defined circular zones. Self-
# generates profiles/DDP_ClimateZones/Config.json on first world load; see
# src/climateZones.ts, which lays down a 3-ring cold gradient centered deep
# in the NW quadrant (coldest there, fading back to unmodified vanilla
# temperature - the map's natural baseline - by the SE), per the project
# owner's own request. Temperature only - no ground texture, tree, or
# weather-VFX changes (the mod's own author confirmed in a Steam comment
# this is temperature-only for now).
#
# DECIDED: a matching NW-only visual snow look isn't included, and won't be.
# Two routes were explored and both rejected:
# "Early Winter or late Fall in Chernarus" (3303988563, confirmed live via
# Steam Web API) reskins via whole-map shared config classes with no
# position-gated option (would snow-reskin the ENTIRE map, not just the
# NW, and its license forbids repacking a partial/regional version); a
# custom scripted particle-effect "snow flurry" confined to the NW was
# technically workable but the project owner decided it wasn't worth
# building without real snow on the ground. Final call: keep just this
# temperature gradient - NW is mechanically colder (frost/hypothermia
# risk), no visual change anywhere on the map.
